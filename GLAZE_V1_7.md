# Glaze V1.7 — Stable Contract

**Version:** `1.7.0`  
**Lifecycle:** Stable compatibility channel / canonical Anchor  
**Stable baseline:** GLAZE UI V1.6 / `1.6.0`  
**Runtime:** `js/glaze-v1.7.0.mjs`

## Contract

Glaze V1.7 establishes the **Glaze** product identity as the current shared GoreeCloud design-and-experience-system release.

V1.7.0 is intentionally a bounded stabilization release. Its public runtime inherits the already accepted V1.6.0 runtime and introduces no unverified V1.7 Development presentation, native-platform, privacy, security, performance, energy, assistive-technology, or adaptive-intelligence behavior.

The richer V1.7 Development implementation remains preserved as historical source provenance and is carried forward through the V1.7.1 Development track.

## Stable guarantees

V1.7.0 preserves the accepted V1.6.0 guarantees and authority boundaries, including presentation-only authority, accessibility precedence, fail-closed provider truth, no inferred authorization, no automatic permission request, no automatic consequential/fallback execution, and independent downstream consumer acceptance.

## Excluded Development behavior

The `1.7.0-dev.47` aggregate and Section 48 source are not part of the V1.7.0 Stable runtime. Their unfinished and unverified qualification obligations are controlled by `GLAZE_V1_7_1_HARDENING.md`.

## Consumer boundary

V1.7.0 being the current shared Stable/Anchor target does not make any downstream GoreeCloud application conformant or production-eligible automatically. Every applicable consumer must complete fresh repository-local V1.7.0 adoption and acceptance.

### Independent application UI identity — mandatory

Every GoreeCloud application MUST deliver its own purpose-built, product-appropriate user interface using the latest applicable, approved Stable Glaze baseline. **Shared design language does not mean identical application screens.** This is an application-level acceptance requirement; the Glaze shared runtime cannot certify an application's visual identity on its own.

- **Shared Glaze foundation:** Use the governed tokens, semantic colors, components, materials, typography, state treatments, focus behavior, motion, accessibility, responsiveness, and supported appearance profiles where applicable. Do not replace them with an unrelated parallel design system solely to appear different.
- **Distinct product experience:** Each application MUST have intentional task-appropriate information architecture, navigation, layout hierarchy, workflows, app icon and glyph treatment, relevant component compositions, and a recognizable product identity. Product-specific accents or specialized UI components MAY extend Glaze within its governed semantic and accessibility boundaries.
- **Functional visual differentiation:** Do not treat a palette swap, logo replacement, or generic identical dashboard template as sufficient evidence that the application has its own designed UI. Different applications may legitimately reuse common Glaze components or patterns where doing so improves usability.
- **Version migration:** When a new Stable Glaze release becomes the approved consumer baseline, independently assess and migrate affected applications, validate their actual rendered behavior, and maintain truthful version declarations. Development-only features MUST NOT be represented as Stable/Anchor features.
- **Consumer-specific verification:** Before claiming conformance, validate representative screens and interactions on each supported form factor, plus applicable navigation, keyboard/touch input, semantic status communication, assistive technology, appearance modes, Reduced Motion, Reduced Transparency, contrast, performance, and core workflows. Retain exact-source evidence in the consuming application's owning repository.
- **Status integrity:** Documentation of this requirement does not prove implementation, user-interface review, acceptance, deployment, or production readiness. Preserve adoption-required or unverified status until the consumer's relevant acceptance gates actually pass.

Governance source: GoreeCloud-wide `Standard — Color, Visual Composition, and Glaze Integration`, particularly **Section 3 (Current Glaze Baseline)** and **Section 13 (Product Identity Within Glaze)**. The consumer application owns its interface implementation and acceptance evidence; `GoreeCloud/glaze` owns shared Glaze contracts and releases.

## Release boundary

Repository Stable/Anchor authority, immutable publication, deployment, and downstream product production acceptance remain distinct transitions. This contract does not fabricate publication evidence.
