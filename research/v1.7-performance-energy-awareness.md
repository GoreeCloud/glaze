## Controlling GoreeCloud governance

### Standard — System-Wide Motion Continuity and Performance

Section 45 inherits the mandatory requirements that optional motion and visual effects must remain responsive, interruptible, resource-aware, accessible, state-safe, and energy-conscious. The standard explicitly requires lower-cost presentation under resource pressure, low-power operation, thermal constraints, constrained hardware, reduced-performance environments, and non-visible/background states. It also requires off-screen or no-longer-useful animation to stop, pause, suspend, or significantly reduce resource use where the platform permits.

The standard further requires state integrity: task completion, navigation, provider truth, accessibility, and application state may not depend on animation completion or optional visual richness.

### Standard — Glaze UI Performance Budget

The approved performance budget remains the numeric qualification authority. Section 45 does not redefine numeric thresholds and does not accept caller-provided frame, CPU, GPU, power, thermal, battery, or energy budgets. Representative exact-revision measurements remain separate acceptance evidence.

### V1.7 Motion Performance dev.25

Section 33 already owns authoritative performance-signal interpretation for runtime pressure, power-saving state, thermal constraint, hardware class, refresh class, performance-degraded state, visibility state, Reduced Motion, and Motion Fatigue budget pressure. Dev.38 composes that resolver rather than creating a second performance authority.

## GoreeCloud Section 45 requirements derived from the research

1. Section 45 must reuse dev.25 environment-signal authority and fail-closed fallback behavior.
2. Advanced themes, material effects, animation, adaptive transitions, decoration, and optional background visual work may lose visual richness when constraints are authoritative.
3. Task continuity, accessibility, responsiveness, semantic state, provider truth, protected semantic color meaning, and critical task availability may not be degraded.
4. Power-saving, thermal constraints, runtime pressure, constrained hardware, low-refresh conditions, performance degradation, non-visible state, Motion Fatigue pressure, and Reduced Motion may simplify optional presentation.
5. Non-visible optional work should suspend or resolve immediately where safe.
6. Continuous decorative animation is not a default requirement.
7. Optional presentation must not force frames merely to remain visually rich.
8. Theme identity and protected semantic color meaning survive simplification; reduced complexity must not become semantic ambiguity.
9. Material simplification should prefer static/solid or bounded lower-cost equivalents when the richer effect is optional.
10. Motion/adaptive-transition simplification delegates to dev.25 so direct manipulation and final-state correctness remain intact.
11. Caller-provided raw blur/shader/particle/layer/frame-forcing controls, thresholds, measurements, or acceptance claims are not accepted by this resolver.
12. Performance, energy, battery, thermal, background-lifecycle, representative-device, rendered, native-platform, assistive-technology, and human-review acceptance remain separate evidence obligations.
13. Source implementation does not promote V1.7, Glaze Motion, downstream consumers, deployment, or production state.

## Independent GoreeCloud design

Dev.38 accepts one governed presentation domain plus the same independently-authorized environment context already supported by Motion Performance dev.25. It returns the inherited performance mode and a deterministic domain-level presentation directive. The resolver deliberately exposes semantic outcomes instead of raw effect values.

A full mode preserves governed presentation. Restrained and simplified modes reduce optional theme/material/motion richness. Minimal mode uses static, solid, immediate, or suspended equivalents. Reduced Motion remains accessibility-authoritative. Background or off-screen optional work is suppressible, idle render loops remain prohibited, and optional visuals cannot request forced frames.
