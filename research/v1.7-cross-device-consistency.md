## Purpose

This record captures exact-revision cross-platform UI research used to derive the bounded Section 42 source requirements. It is research provenance, not rendered, native-platform, assistive-technology, representative-device, performance, energy, or human-review acceptance evidence.

The GoreeCloud implementation remains independent and uses the existing Native Glaze Kits, form-factor, theme, component, Studio/Inspector, and Accessibility Continuity foundations as its authority-preserving base.

## Cross-source findings

The reviewed projects support these implementation-neutral requirements:

1. Preserve the same semantic action, state, and relationship even when the native control or composition differs.
2. Platform-native controls and rendering primitives are compatible with cross-device consistency when semantic meaning, accessibility, and authority remain unchanged.
3. Adaptive layout is not semantic divergence: mobile, tablet, desktop, TV, wearable, and posture-aware presentations may use different composition while preserving task identity and interaction meaning.
4. Platform appearance and accessibility settings must remain platform/caller-authoritative.
5. A cross-device design contract should compare meaning and authority, not screenshot similarity or pixel identity.
6. Motion-family meaning can remain shared while timing, curves, paths, primitives, and performance behavior remain native implementation details.
7. Cross-device evaluation must not select a “best” platform or rank targets; the requirement is consistency of governed semantics.

## GoreeCloud-native Section 42 decisions

The dev.35 layer therefore:

- Requires common semantic vocabulary, color roles, state vocabulary, motion language, material hierarchy, interaction principles, accessibility expectations, and authority boundaries.
- Reuses Native Glaze Kits v1.2 so Android/Jetpack Compose, Apple/SwiftUI, Web, and supported Linux native mappings keep platform-specific bridges and implementation authority.
- Accepts different form-factor profiles and native mappings across targets.
- Explicitly does not require pixel-identical presentation, identical native controls, identical layout composition, identical animation timing/curves/paths, identical rendering primitives, identical input bindings, or identical windowing mechanics.
- Rejects caller attempts to inject screenshot-similarity scores, raw visual measurements, raw animation values, ranking, ratings, or a winner into the Section 42 semantic resolver.
- Requires caller/provider authority for semantic state/color/motion truth where truth is claimed.
- Keeps native implementation, platform capability, accessibility settings, provider truth, application state, permission, authorization, navigation execution, and acceptance outside Glaze authority.
- Keeps all cross-platform rendered/native/assistive-technology/representative-device/performance/energy/human review separately evidence-gated.

## Incorporation statement

No third-party source code, components, layout algorithms, numeric dimensions, animation timing values, easing curves, spring constants, native controls, assets, fonts, icons, visual identity, trademarks, or branding are incorporated by this tranche. The sources above were used only to extract architectural requirements and cross-platform consistency principles.

## Acceptance boundary

Source behavior and exact-source validation do not establish Section 42 completion. Section 42 remains incomplete until applicable cross-platform rendered, native-platform, assistive-technology, representative-device, measured-performance, energy, and human cross-device review evidence is independently accepted.
