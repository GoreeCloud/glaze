## Purpose

This record captures external component-system and accessibility research used to derive bounded Section 38 requirements. It is research provenance, not acceptance evidence. No reviewed upstream component source, animation values, assets, or visual identity are incorporated by this tranche.

The GoreeCloud implementation remains an independent extension of the historical Glaze UI dev.10 component foundation.

## Sources reviewed

- Repository: https://github.com/radix-ui/primitives

- Requirement lesson: reusable primitives are easier to compose and adapt when behavior is expressed through explicit semantic parts rather than opaque monolithic presentation.
- GoreeCloud decision: Section 38 preserves component identity and semantic contracts while keeping animation selection outside local component implementation.

## Cross-source findings

The sources converge on several useful architectural lessons:

1. Components should expose explicit semantic contracts rather than forcing consumers to infer behavior from appearance.
2. Accessibility, keyboard interaction, focus, and state semantics must survive styling and animation changes.
3. Component composition should remain separable from product/provider truth.
4. A design-system component layer should not require consumers to manipulate low-level animation physics merely to express ordinary state relationships.
5. Platform-specific implementation details should be allowed to differ while semantic behavior remains consistent.
6. Upstream maintenance state matters; a mature component library can be useful research without becoming an architectural dependency.

## GoreeCloud-native Section 38 decisions

The bounded dev.30 layer therefore:

- Retains the historical 14-component dev.10 catalog instead of importing an upstream catalog.
- Preserves dev.10 as v1.1 Section 25 provenance and does not relabel it as v1.2 Section 38.
- Gives each component an explicit allowlist of applicable Glaze semantic transition relationships.
- Requires externally authoritative transition occurrence before motion is eligible.
- Requires externally authoritative semantic state for color/material state-change relationships.
- Continues requiring authoritative connected identity where Glaze Bloom or Trace semantics require it.
- Rejects direct Signature Motion family selection and raw timing/easing/spring/keyframe/path/physics controls.
- Forbids arbitrary component-local animations as a substitute for Glaze semantic relationships.
- Preserves Reduced Motion, focus, navigation, keyboard semantics, task continuity, semantic color policy, and provider/application truth.
- Treats specialized Notification/Activity truth and motion as Section 36 authority rather than recreating it in Section 38.
- Uses dev.25 Motion Performance to simplify or remove optional animation without changing authoritative state.
- Keeps all rendered, native-platform, assistive-technology, performance, representative-device, energy, and human-motion acceptance separately evidence-gated.

## Security and privacy review

No researched project grants GoreeCloud additional authority. Section 38 remains presentation-only and does not create provider truth, execute actions, navigate, persist themes, collect telemetry, inspect private content, or infer security/privacy state.

## Incorporation statement

No third-party source code, component implementation, numeric animation values, curves, spring parameters, assets, icons, fonts, visual identity, trademarks, or product branding are incorporated by this research. The sources were used to extract requirements and architectural lessons only.

## Validation boundary

Successful behavior in the researched projects is not evidence for Glaze UI. The GoreeCloud implementation must pass its own exact-revision validators, retained V1.7 regressions, V1.6 Anchor-preservation gates, accessibility boundaries, and later representative acceptance work.
