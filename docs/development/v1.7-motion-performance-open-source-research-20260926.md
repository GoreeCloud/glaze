## Controlling GoreeCloud governance examined

### Standard — System-Wide Motion Continuity and Performance

This mandatory GoreeCloud standard requires motion to remain responsive, accessible, stable, interruptible, resource-aware, and state-safe. Dev.25 derives these requirements from it:

- application state never depends on animation completion;
- user input and direct manipulation outrank decorative motion;
- ordinary interface motion should prefer lower-cost, compositor-friendly techniques where appropriate;
- unnecessary layout recalculation, repainting, main-thread blocking, continuous rendering, GPU overdraw, and background animation work should be avoided;
- optional visual complexity should reduce under runtime/resource pressure, low-power operation, thermal constraints, constrained hardware, reduced-performance environments, and background/minimized/obscured state;
- off-screen or no-longer-useful animation should stop, pause, suspend, or significantly reduce resource use where the platform permits;
- Reduced Motion replaces or removes nonessential movement instead of merely speeding it up;
- effects that cannot satisfy responsiveness must be optimized, simplified, conditionally reduced, replaced with a lower-cost implementation, or removed.

The standard requires representative performance evidence before release-quality acceptance. Dev.25 therefore implements source policy only.

### Standard — Glaze UI Performance Budget

The approved v1.0 performance budget remains the numeric qualification authority. Dev.25 references but does not redefine or automatically satisfy these existing thresholds:

- resolver p95 ≤ 10.0 ms;
- resolver p99 ≤ 16.7 ms;
- interaction-to-painted-update p95 ≤ 100 ms;
- interaction-to-painted-update p99 ≤ 200 ms;
- severe frame-stall rate ≤ 0.01;
- catastrophic foreground stalls = 0;
- task-state resets = 0;
- required page reloads = 0;
- automatic authority actions = 0;
- minimum samples: resolver 200, interaction paint 30, idle frames 120, active frames 240.

The governing budget requires real measurements tied to an exact revision and representative environment. Missing, stale, revision-mismatched, or environment-mismatched evidence remains open. The dev.25 resolver rejects acceptance-measurement payloads so it cannot be used to manufacture a pass.

### Standard — Glaze Motion

Glaze Motion reinforces progressive complexity, compositor-friendly transforms/opacity for ordinary UI motion where appropriate, suspension of off-screen/background work, avoidance of idle render loops, direct-manipulation continuity, graceful fallback, Reduced Motion, and evidence-backed conformance.

The separate Glaze Motion 0.6 lifecycle remains Experimental. Section 33 consumes compatible principles without promoting that lifecycle.

## GoreeCloud requirements derived from the research

1. Motion performance adaptation is presentation policy, not a source of application, power, thermal, hardware, refresh, visibility, provider, or performance truth.
2. Non-neutral environment signals require explicit caller/platform authority. Untrusted signals fail closed to neutral.
3. Reduced Motion outranks visual expression and uses the existing semantic equivalent system.
4. Runtime pressure, power-saving state, thermal constraints, constrained hardware, low-refresh conditions, performance-degraded state, authoritative non-visible state, and dev.24 motion-budget pressure may reduce optional richness.
5. Multiple simultaneous constraints should produce stronger simplification than one ordinary constraint.
6. Severe runtime pressure, critical thermal state, or authoritative off-screen/background/obscured state should use minimal optional motion.
7. Direct manipulation remains input-driven even when post-release settling is reduced.
8. Off-screen/background/obscured optional animation should suspend or immediately resolve where safe.
9. Idle render loops are not ordinary UI behavior.
10. Ordinary motion should prefer transforms, opacity, bounded clipping, or suitable platform-native compositor primitives where they satisfy semantic requirements.
11. Layout-driven animation, synchronous measurement loops, unbounded repainting, continuous main-thread rendering, and unbounded shader complexity should not be used when an equivalent lower-cost technique exists.
12. Applications cannot supply raw timing/physics controls, frame budgets, performance thresholds, or acceptance measurements through this resolver.
13. The approved Glaze UI Performance Budget remains an external qualification authority. The resolver may reference it but may not infer acceptance.
14. Measured frame pacing, interaction latency, thermal/power behavior, low-end hardware behavior, low/high-refresh behavior, rendered/native/assistive-technology behavior, and human review remain separate evidence obligations.
15. Glaze Motion 0.6 remains Experimental and is not promoted by Section 33.

## Independent GoreeCloud design

Dev.25 accepts governed semantic motion context plus explicitly authoritative non-neutral environment signals. It resolves one of five presentation modes: Full, Restrained, Simplified, Minimal, or Reduced Motion. Untrusted non-neutral signals are ignored and recorded as neutral fallbacks.

The resolver composes dev.24 motion-budget pressure, preserves direct manipulation, prefers low-cost presentation techniques, suspends optional non-visible work, and produces deterministic fallbacks for task transitions, connected transformations, adaptive recomposition, materials, skeletons, decorative motion, and continuous decorative motion.

The source imports the V1.6 performance-diagnostics contract to expose the approved performance budget as a reference. It rejects measurement payloads and explicitly states that representative exact-revision evidence is still required.

This research record documents engineering influence only. No upstream source code, exact third-party timing values, curves, components, assets, or distinctive third-party visual identity is reproduced.
