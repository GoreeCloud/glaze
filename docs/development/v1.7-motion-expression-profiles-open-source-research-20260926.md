## GoreeCloud requirements derived from the research

1. Motion character should be selected through semantic profiles, not exposed as raw duration/easing/spring/physics controls.
2. A profile should adjust a coherent set of motion relationships rather than only speeding up or slowing down every animation.
3. Repeated productivity interactions should remain restrained even when an expressive profile is active.
4. Accessibility and performance constraints must override optional richness without corrupting application state or rewriting the user's stored preference.
5. Direct manipulation must continue tracking user input even when Reduced Motion suppresses post-gesture travel or settling.
6. Expressive presentation must remain semantic and bounded; it must never mean continuous animation.
7. The profile layer must connect to GoreeCloud's existing Personalization 2.0 `motionIntensity` model instead of creating a second preference authority.

## Independent GoreeCloud design

The existing V1.7 Personalization 2.0 source already defines `motionIntensity` values `minimal`, `standard`, and `expressive`. Dev.21 maps those existing semantic values to Section 29 profiles:

- `minimal` → **Calm**
- `standard` → **Balanced**
- `expressive` → **Expressive**

The resolver preserves both the selected profile and the effective profile. Accessibility or authoritative performance pressure may reduce the effective profile while leaving the selected preference untouched. Reduced Motion additionally replaces travel, connected transformation, decorative movement, and post-action settling with lower-motion semantic equivalents while preserving direct-manipulation tracking and authoritative application state.

This research record documents engineering influence only. No upstream source code, exact motion values, curve definitions, component implementation, or distinctive third-party visual identity is reproduced.
