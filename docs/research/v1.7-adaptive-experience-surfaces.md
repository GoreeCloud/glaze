# V1.7 Adaptive Experience Surfaces — Reforge Research

## Purpose

This research record informs the independent GoreeCloud implementation of the remaining V1.7 Section 48 adaptive experience surfaces. It records useful public concepts without importing an upstream product, component implementation, architecture, branding, or application logic.

## Sources reviewed

### Android adaptive layouts

Android's canonical adaptive-layout guidance uses purpose-specific patterns such as list-detail and supporting panes, and emphasizes state hoisting so recomposition does not erase application state. Useful concepts: task continuity across layout changes, semantic pane roles, and purpose-built compact/expanded behavior.

### GNOME / libadwaita adaptive layouts

GNOME/libadwaita adaptive widgets expose layouts that can split or collapse while preserving application content and navigation relationships. Useful concepts: semantic adaptation rather than brand-specific breakpoints, and bounded presentation changes that do not redefine application state.

### W3C WAI-ARIA Authoring Practices

WAI-ARIA Authoring Practices separates semantic role/state from visual styling and defines predictable keyboard/focus interaction for composite widgets. Useful concepts: accessible names/roles, focus continuity, keyboard equivalence, state truth independent of color/motion, and predictable reading/focus order.

## GoreeCloud synthesis

The independent Glaze implementation applies these concepts through existing GoreeCloud-owned foundations:

- Task Continuity for workspace recomposition;
- Accessibility Continuity for large text, Reduced Motion, Reduced Transparency, Increased Contrast, Forced Colors, screen reader, switch, voice, touch-assistance, and keyboard modes;
- Privacy and Authority Boundaries for privacy/security/provider truth;
- Performance and Energy Awareness for optional-richness degradation without semantic degradation;
- Expression System Core for semantic geometry, containment, typography, composition, and motion expression.

The resulting surfaces remain presentation-only and fail closed when authoritative state is unavailable.

No third-party component implementation is incorporated. No mechanical rewriting or line-by-line translation was performed.
