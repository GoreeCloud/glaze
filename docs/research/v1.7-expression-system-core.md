# Glaze UI V1.7 dev.40 — Expression System Core Research

**Research date:** 2026-09-30  
**Scope:** Semantic Geometry, Visual Scale and Emphasis, Expressive Typography, Semantic Containment, Component Expression, and governed Expression Resolution.

## Sources reviewed

- Microsoft Fluent 2 guidance for semantic design-token layers, typography hierarchy, shape vocabulary, and accessibility-informed structure.
- W3C WCAG 2.2 Understanding guidance for Reflow and Text Spacing.
- Existing GoreeCloud V1.7 accessibility-continuity, visual/motion-direction, advanced-theme, and performance/energy foundations.

## Reforge boundary

External material informs requirements and semantic boundaries only. No Fluent UI component implementation, design-token values, raw visual constants, assets, fonts, icons, motion specifications, or visual identity are incorporated. W3C guidance is used as accessibility requirements context rather than copied implementation.

Third-party implementation is not incorporated by this tranche.

## Resulting GoreeCloud requirements

The dev.40 source foundation accepts semantic expression intent instead of unrestricted geometry, typography, spacing, color, material-effect, animation, or performance values. Supporting, Standard, Prominent, and Hero emphasis are separate from semantic severity. Expressive typography must remain compatible with large text, reflow, and user text-spacing adaptation. Containment communicates relationship without requiring decorative nesting. Component expression remains bounded by semantic roles.

Accessibility outranks optional expression. Performance pressure may reduce optional richness without changing task continuity, semantic meaning, direct manipulation, or authoritative state. Personalization may change expression; personalization must not change truth.

This research record is not rendered, native-platform, assistive-technology, representative-device, performance, energy, cross-platform, or human visual acceptance evidence.
