# Glaze UI Wearable Components — Deferred Mapping

**Current shared authority:** GLAZE UI V1.6 / `1.6.0` Anchor  
**Wearable status:** Development/reference mapping only; no first-class wearable capability is currently promoted.

Wearable adaptations may derive from the current semantic component model while using platform-specific controls, navigation, input, and surface conventions. Components must preserve action meaning, accessibility labels, focus and reachability, confirmation behavior, semantic state, provider truth, and readable status at small display sizes.

Wearable layout must prioritize glanceability and task continuity rather than reproducing phone or desktop composition at reduced size. Touch targets, rotary or Digital Crown navigation, focus movement, dismissal/back behavior, and accessibility semantics must follow the applicable native platform and claimed product scope.

The retained Wear OS/watchOS reference projects and native-evidence template are Development/audit material. They are not current V1.6 Anchor entrypoints and do not independently establish application conformance.

A wearable component mapping becomes production-relevant only through exact-current native evidence and application-specific acceptance. Source validation, compilation, simulator/emulator packaging, or historical runtime checks alone do not establish representative real-device operation, accessibility acceptance, production signing, consumer conformance, or lifecycle promotion.
